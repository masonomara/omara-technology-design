## Phase 4 — Codebase: Low Priority / Consistency ✅

### 4.1 — Unify all files to the same code style

Every file should read like it was written by the same person. Audit for:

- **Import order**: external packages first, then internal (`@/`), then relative (`./`), then CSS modules last. Apply consistently across every component file.
- **Const naming**: `PascalCase` for types/interfaces, `SCREAMING_SNAKE` for top-level constants, `camelCase` for everything else. `ENEMY_COUNT`, `NAV_LINKS`, `EMAIL_ADDRESS` — all already follow this. Make sure no file has bare magic strings or numbers that appear more than once without a named const.
- **Spacing**: one blank line between imports and the first const/type; one blank line between sections within a component.
- **Comments**: use `// ─── Section ───` banners for long files (already started in `Game.tsx` — carry this convention to any file over ~80 lines).
- **Exports**: default exports for page components and layout; named exports for utilities and hooks.

### 4.2 — Remove `layout` and `objectFit` deprecated Next.js props

**File:** `src/app/components/About.tsx:152–153`

The `layout="fill"` and `objectFit="cover"` props on `<Image>` are deprecated in Next.js 13+. Replace with:

```tsx
<Image
  src="/siteHeadshot.png"
  alt="Headshot of Mason O'Mara"
  fill
  style={{ objectFit: "cover" }}
  className={styles.cardImageTwo}
/>
```

## Tense Reference

For every piece of copy, apply this rule:

- **Present tense** for what the studio does, what the services include, what the process looks like — anything describing the system as it exists now.
- **Past tense** only for specific, completed project outcomes ("sales went from 7% to 49%", "launched with 500 users").
- **Avoid future tense** in marketing copy — "we will build your product" weakens trust. "We build products" is stronger.
